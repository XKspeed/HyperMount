常见问题

按出问题的环节分组。动手前先确认一件事：救砖界面必须是一份确认可用的 SystemUI。

环境与安装

打开提示环境检查不过，说模块不对

应用只认作者为 XKspeed 的 systemui_mount 模块。检查：

  • 模块是否真的刷入并重启过（Root 管理器里能看到且为启用状态）；
  • 装的是不是同名但非本项目的模块——同名不同作者会被拦，这是故意的，脚本接口对不上会静默失败；
  • Root 是否真的可用：应用走的是常驻 su shell，授权被拒会直接表现为读不到配置。
提示「未找到 MT 管理器」

选 apk 用的就是 MT 的选择器（正版 bin.mt.plus 优先，其次是共存版 bin.mt.plus.canary），不会退回系统文件选择器。装一个即可。

另外注意：Android 11 之后有包可见性限制，如果两种 MT 都装了却仍提示未找到，多半是系统把查询挡了，重启一次应用再看。

装上新版本提示「应用未安装」

两个原因：versionCode 没递增，或签名变了。正式版一直用同一套密钥签名，正常覆盖升级不会有问题；如果你装过自行编译的包，需要先卸载再装。

卸载会清掉应用内的设置（模块里的配置不受影响）。

音量键

音量键显示「未识别」，但音量键明明能用

「能用」和「能读到事件」是两件事。应用要求按键真的产生一次 KEY_VOLUMEUP / KEY_VOLUMEDOWN 事件才算识别通过，只是声明了能力位不算。

校验时按提示真的按一下音量键；如果一直读不到，可能按键被系统手势或辅助功能占用了，换一个按键组合或关掉相关功能再试。

系统升级后又要重新校验

这是设计如此。系统升级会改变输入设备号，旧结果继续用就是「按了没反应」。应用记录校验时的具体版本（如 4.0.24.0.WOCCNXM），对不上就作废旧值并重新拉起校验面板。

救砖时按音量 + 没反应
  • 守护是否在跑：状态卡显示「未在运行」就不会响应按键；
  • 音量键是否已识别：未识别说明设备号没写进模块配置；
  • 是否处于「仅日志」或「完全禁用」模式：这两种模式不执行救砖。

实在不行进 Recovery 处理，别反复重启等它自己好。

自动救砖

换了待测界面黑屏了，但没有自动换回

按可能性排：

  • 系统先动手了：AMS 自己的崩溃上限（默认 12）比设定的阈值更早触发，SystemUI 被系统重启成原版或被收走。这种情况需要开「屏蔽系统救援」。
  • 崩溃次数没到阈值：单次崩溃但阈值较高。这类情况靠「卡死检测」兜——日志疯长会直接触发，不看次数。
  • 守护没起来：模式为「仅日志」或「完全禁用」。
开启增强救砖后，为什么「屏蔽系统救援」是灰的

两者绑死了。增强救砖要靠崩溃次数累积到阈值才动作，如果不屏蔽系统救援，系统会先崩到自己的上限把 SystemUI 收走，自动救砖根本没机会执行。所以开启增强时强制打开，不可关闭。

崩溃上限 30 是怎么来的

「日志 + 救砖」模式（不开增强）下自动设成 30。系统默认的 12 太紧，等不到人按音量键就已经被收走。开了增强救砖之后这个值可以自己调。

救回之后界面还是旧的 / 还是崩的

替换后需要等 SystemUI 重启完成，这段时间屏幕可能是黑的，属于正常。设置里的「等待超时」就是给这个留的时间，太短会误判失败。

如果反复救回又崩，说明救砖界面那份本身在当前系统上不可用，换一份从当前系统提取的再试。

日志目录

改了日志目录，设置页没变化

正常情况下选完立刻写入并回读校验，写入失败会弹提示而不是静默失败。如果确实没变，去「应用日志」看这几行：

I/选目录 解析出 <路径>（来源 data.uri）
I/选目录 提交 LOG_DIR=<路径>
I/状态 LOG_DIR 配置=<值> → 界面显示 <值>

三行齐全且值一致就是写进去了，可能是页面还没刷新，退出设置页再进。

选不到 /data/adb 这类目录

系统文件夹选择器（SAF）看不到 root 专属目录。日志目录选 /storage/emulated/0/... 即可；一定要写到 /data/adb 时，在弹窗里手动填路径。

注意脚本以 root 身份运行，写 sdcard 没有权限问题。

主页测试

主页选 apk 提示「这个包不能装」

那是 com.android.systemui。主页是给普通 apk 做崩溃测试用的，把系统界面本体装进去很容易直接黑砖。要换系统界面，去「界面」页。

主页能测不是 SystemUI 的应用吗

可以。主页不校验包名，测的是「装上、跑起来、会不会崩」。目标包名只用于筛日志，和选的两个 apk 没有绑定关系——测插件时崩溃日志会记在宿主包名下。

主页跑完，日志在哪

在设置页「日志目录」指定的位置，文件名是 logcat_<包名>_<时间>.log。只有运行模式带日志时才会出现「日志目录」这张卡。

更新与升级

检查更新一直失败

应用会按顺序试 GitHub 直连和几个镜像（gh-proxy、ghproxy、ghfast、moeyy、jsDelivr），任何一个通了就算成功。全都不通时：

  • 确认网络能出网（部分校园网 / 企业网会拦）；
  • 过一会儿再试，镜像站偶尔集体抽风；
  • 直接来官网点镜像下载。
新版本能直接覆盖安装吗

能。正式版固定签名，versionCode 递增，直接覆盖。更新只换应用，模块配置和已选的界面文件都不受影响。

风险相关

会不会影响系统 OTA

模块通过挂载替换 SystemUI，OTA 前后行为以模块说明为准。升级系统前建议先在应用里停止守护、把界面还原成原版，升级后再重新走一遍模块安装与音量键校验。

最坏的情况是什么

SystemUI 起不来 → 黑屏但系统仍在运行 → 靠音量键 / Recovery 换回。真正救不回来的是「救砖界面本身也不可用」和「模块被卸载但界面还是替换状态」。所以第一次用请务必确认救砖界面可用。

没找到答案？提个 issue，附上应用日志里对应的那几行。
