# 常见问题

按出问题的环节分组 动手前先确认一件事：**救砖界面必须是一份确认可用的 SystemUI** 

## 环境与安装 {#env}

::: details 打开提示环境检查不过 说模块不对
应用只认作者为 `XKspeed` 的 `systemui_mount` 模块 检查：

- 模块是否真的刷入并重启过（Root 管理器里能看到且为启用状态） 
- 装的是不是同名但非本项目的模块——同名不同作者会被拦 这是故意的 脚本接口对不上会静默失败 
- Root 是否真的可用：应用要 root 才能读模块里的东西 授权被拒就会一片空白 
:::

::: details 提示「未找到 MT 管理器」

- 你真的装了 MT 管理器吗
- 隐藏应用列表 发力了
:::

## 音量键 {#volume}

::: details 音量键显示「未识别」 但音量键明明能用
鉴定为不适配 联系作者
:::

::: details 系统升级后又要重新校验
系统更新后其音量键获取途径地址可能发生变化<br>故需重新校验
:::

::: details 救砖时按音量 + 没反应
- 守护是否在跑：状态卡显示「未在运行」就不会响应按键 
- 音量键是否已识别：未识别说明设备号没写进模块配置 
- 是否处于「仅日志」或「完全禁用」模式：这两种模式不执行救砖 

实在不行进 Recovery 处理
:::

## 自动救砖 {#auto}

::: details 换了待测界面黑屏了 但没有自动换回
按可能性排：

- **系统先动手了**：系统自己数到一定次数（默认 12）就把界面收走 比设定的阈值更早 这种情况需要开「屏蔽系统救援」 
- **崩溃次数没到阈值**：单次崩溃但阈值较高 这类情况靠「卡死检测」兜——日志疯长会直接触发 不看次数 
- **守护没起来**：模式为「仅日志」或「完全禁用」 
:::

::: details 开启增强救砖后 为什么「屏蔽系统救援」是灰的
设计如此 不开等着成砖吗
:::

::: details 救回之后界面还是旧的 / 还是崩的
替换后需要等 SystemUI 重启完成 这段时间屏幕可能是黑的 属于正常

如果反复救回又崩 说明救砖界面那份本身在当前系统上不可用 换一份从当前系统提取的再试 
:::

## 日志目录 {#logdir}

::: details 提示「未指定日志目录」 开不了测试
你没指定日志目录
:::

::: details 改了日志目录 设置页没变化
正常情况下选完立刻写入并回读校验 写入失败会弹提示而不是静默失败 如果确实没变 去「应用日志」看这几行：

```
I/选目录 解析出 <路径>（来源 data.uri）
I/选目录 提交 LOG_DIR=<路径>
I/状态 LOG_DIR 配置=<值> → 界面显示 <值>
```

三行齐全且值一致就是写进去了 可能是页面还没刷新 退出设置页再进 
:::

::: details 选不到 /data/adb 这类目录
你闲的没事放这干啥
:::

## 主页测试 {#main}

::: details 主页选 apk 提示「这个包不能装」
这个设计之初是给组件用的 装SystemUI会导致崩溃
:::

## 风险相关 {#risk}

::: details 会不会影响系统 OTA
模块通过挂载替换 升级系统前建议先在应用里停止守护 把界面还原成原版 升级后再重新走一遍模块安装与音量键校验 
:::

::: details 最坏的情况是什么
SystemUI 起不来 → 黑屏但系统仍在运行 → 靠音量键 / Recovery 换回 真正救不回来的是「救砖界面本身也不可用」和「模块被卸载但界面还是替换状态」 所以第一次用请务必确认救砖界面可用 
:::
