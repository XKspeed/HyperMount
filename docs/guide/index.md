# 使用教程

这篇写给第一次用的人 从装模块到换第一个界面 正常十几分钟能走完 

每一步都写了「你应该看到什么」 对不上就停下来 别硬往下走——界面替换这类操作 跳过一步检查 后面往往是黑屏 

## 先弄明白它在做什么 {#what}

手机的状态栏 通知栏 最近任务 锁屏 都是 `com.android.systemui` 这个系统应用画出来的 下文简称 **SystemUI** 改主题 换状态栏样式 本质都是在动它 

SystemUI 有个特点：**它崩了 屏幕就没了** 不是死机 是没人负责画画了 你能看到黑屏 但系统其实还活着 

HyperMount 干的事很单一：

1. 往模块目录里放一份 SystemUI 安装包 
2. 模块开机时把这份包挂载到系统原来的位置（不修改系统分区 卸载模块即恢复） 
3. 重启 SystemUI 让它加载新的这一份 
4. 之后一直盯着它 崩了就把原来那份换回去 再重启一次 

所以要装两样东西 缺一不可：

| 东西 | 是什么 | 干什么 |
| --- | --- | --- |
| **模块** `systemui_mount` | 一个 Magisk / KernelSU / APatch 模块 | 负责挂载 备份 执行替换脚本 |
| **应用** HyperMount | 一个普通 App | 负责选包 写配置 调脚本 看日志 |

应用本身没有任何特权 它只是替你敲命令 真正的活都是模块里的脚本在干 

## 它有两种用法 别弄混 {#two-ways}

底部只有三个页面：**界面** **主页** **设置** 前两个看着像 其实是两条完全独立的流程：

| 项目 | 界面页 | 主页 |
| --- | --- | --- |
| 干什么 | 换 SystemUI 并守护 | 装任意 APK 看它崩不崩 |
| 依赖模块 | 依赖 脚本在模块里 | 不依赖 脚本在 App 私有目录 |
| 必须选什么 | 两份 SystemUI 安装包 | 待测 APK 救砖 APK 可选 |
| 典型场景 | 试试新做的状态栏 | 测一个插件 / 应用的新版本 |
| 崩了怎么恢复 | 换回救砖界面 | 装回救砖 APK（可选） |

**第一次用 先走界面页**  主页等界面页跑通之后再玩 

## 开干之前 {#before}

逐项对一遍 缺哪项先补：

| 项目 | 要求 | 怎么确认 |
| --- | --- | --- |
| 系统 | Android 15（API 35）及以上 HyperOS / MIUI 系 | 设置 → 我的设备 → 系统版本 |
| 架构 | arm64 | 现在绝大多数机器都是 |
| Root | Magisk / KernelSU / APatch 任一 且已授权 | 打开管理器能看到模块列表 |
| MT 管理器 | **必须装** | 应用商店或官网 正版/共存版都行 |
| 模块 zip | 必须来自本项目的 Release | 作者是 `XKspeed` |
| App APK | 同一个 Release 里的 | 版本号不用和模块完全一致 |
| 救砖包 | 一份**确认能开机**的 SystemUI | 见 1.3 与第 4 节 |

> **这不是免 Root 工具**  没有 Root 脚本一行都执行不了 装不上模块就别往下看了 装上也用不了 

## 1 · 装模块 {#step1}

### 1.1 下载

在 [Release 页面](https://github.com/XKspeed/HyperMount/releases/latest) 下模块压缩包 文件名形如 `systemui_mount-v1.5.5.zip` **别解压** 

### 1.2 先看你的管理器要不要装「元模块」

这一步只影响 KernelSU / APatch 用户 Magisk 可以跳过 

| 管理器 | 谁负责挂载 | 你要做什么 |
| --- | --- | --- |
| Magisk | 自带 magic mount | 跳过本节 |
| KernelSU | 需要元模块 | 装一个 |
| APatch | 需要元模块 | 装一个 |

KernelSU 和 APatch 只负责给 root 不管「把模块里的文件挂到系统分区」 这个活得靠**元模块**（metamodule）来完成 没有它 模块装了也是白装 

常用的四个：

| 元模块 | 仓库 | 说明 |
| --- | --- | --- |
| Mountify | [GitHub](https://github.com/backslashxx/mountify) | 通用 KernelSU / APatch 都能用 |
| Hybrid Mount | [GitHub](https://github.com/Hybrid-Mount/meta-hybrid_mount) | 混合挂载 兼容性取向 |
| Magic Mount-rs | [GitHub](https://github.com/Tools-cx-app/meta-magic_mount-rs) | Rust 重写 行为尽量贴近 Magisk |
| NoMount | [GitHub](https://github.com/maxsteeel/nomount) | **仅支持 5.10 以上 GKI 内核** 老内核别选 |

装法和其他模块一样：管理器里「从本地安装」 选 zip 刷完重启 **只装一个** 几个挂载器同时跑会互相抢挂载点 

不确定内核版本：MT 管理器打开 `/proc/version` 看第一行 或者用设备信息类应用看「内核版本」 

### 1.3 先把界面塞进压缩包 {#put-apk}

**顺序很重要：先放文件 再刷模块** 

元模块是在**刷入 / 开机扫描**的时候去看模块目录里有什么 然后决定挂哪几个文件 你如果先刷了空模块 再往目录里补 apk 它那一轮已经扫完了 不会重新识别——表现就是模块装着 界面一点没变 

所以要在刷之前 把 `MiuiSystemUI.apk` 放进 zip 里 

**第一步 拿到文件**  用 MT 管理器打开 `/system_ext/priv-app/MiuiSystemUI/MiuiSystemUI.apk` 这是你手机正在用的那份 复制到下载目录 

**第二步 塞进 zip**  用 MT 打开模块 zip（点一下选「打开压缩包」 别解压） 进到：

```
system_ext/priv-app/MiuiSystemUI/
```

点右下角 `+` → 添加文件 → 选刚复制出来的 `MiuiSystemUI.apk` 退出时 MT 会问要不要更新压缩包 确认 

放好之后 zip 内部应该是这个结构：

```
systemui_mount-v1.5.5.zip
├── META-INF/
├── config/
├── system_ext/
│   └── priv-app/
│       └── MiuiSystemUI/
│           └── MiuiSystemUI.apk   ← 就是它
├── customize.sh
├── module.prop
└── service.sh
```

> **别把整个文件夹再压一层**  如果你解压后重新压缩 很容易变成 `xxx.zip/systemui_mount-v1.5.5/module.prop` 管理器读不到根目录的 `module.prop` 直接报「不是有效的模块」 压缩时选中**里面的所有文件和文件夹**再压 不要在它们外面多包一层 

**这份文件同时就是你后面的救砖包**  下载目录里那份别删 第 4 节还要选它 

### 1.4 刷入模块

Magisk：底部「模块」→ 从本地安装 → 选改好的 zip → 等它跑完 → 右下角「重启」 
KernelSU / APatch：同样在「模块」页 点安装 选 zip 

刷入时屏幕上会滚一段文字 最后是 `✅ 安装完成！` 上面还会打印这个版本的更新说明 没看到这行就是没刷进去 重来 

刷完**必须重启** 挂载是开机时建立的 

### 1.5 重启后确认

重启后回模块列表 应该能看到：

- 名称：`日志版挂载界面`
- 包名/ID：`systemui_mount`
- 作者：`XKspeed`
- 描述里有时间和「状态」

描述里如果写着「待重启」 说明还没生效 再重启一次 

挂载到底通没通 最直接的验证是后面换一次界面——能换成功 就说明挂载正常 想当场看 用 MT 打开 `/system_ext/priv-app/MiuiSystemUI/MiuiSystemUI.apk` 看修改时间是不是你塞进去那一刻 大小是不是和你放的那份一致 

### 1.6 挂载没生效怎么排查 {#mount-fail}

按这个顺序过一遍 多数问题在前三条：

| 现象 | 大概率原因 |
| --- | --- |
| 模块已安装 界面毫无变化 | zip 里没放 apk 或放错了路径（见 1.3） |
| 模块刷入时报「不是有效的模块」 | 压缩时多套了一层文件夹 |
| KernelSU / APatch 下所有模块都不生效 | 没装元模块 |
| 装了元模块还是不生效 | 装了两个以上 互相打架 只留一个 |
| NoMount 装了没反应 | 内核低于 5.10 换 Mountify 或 Hybrid Mount |
| 放了文件仍然不行 | 文件名不是 `MiuiSystemUI.apk` 或 zip 内路径不对 |
| 重启后模块描述还是「待重启」 | 没真正重启 或者模块被管理器禁用了 |

还是不行 看 @Mari0us 写的这篇 讲的是挂载不生效的排查思路：

[在酷安打开这篇](coolmarket://www.coolapk.com/feed/73074049)

### 1.7 装错版本会怎样

应用启动时会检查模块作者 不是 `XKspeed` 的会直接被拦在引导页 提示「当前模块不是 XKspeed 版」 

这不是防伪 是**脚本对不上**：别的模块没有 `webctl.sh` 没有这套配置项 应用调不动它 

## 2 · 装应用与首次引导 {#step2}

安装 APK 打开 会依次走五步 

### 第一步：欢迎

这一屏列了四条功能 看一眼就知道这套东西能干什么：

- **崩了自动换回**：崩溃到阈值 / 日志疯长 / 堆栈刷屏 任一命中就装回救砖包
- **音量键兜底**：屏幕点不动时 音量 + 直接换回 音量 − 取消
- **不碰系统分区**：模块挂载 卸载模块就回到原界面
- **也能测任意 APK**：主页是独立流程 不依赖模块守护

点继续 

### 第二步：须知

写明了改系统界面的风险和免责 勾选「我已阅读并了解以上内容」 才能继续 

### 第三步：环境检查

应用会自己查三件事：

| 检查项 | 通过的样子 | 没通过怎么办 |
| --- | --- | --- |
| Root 权限 | 已授权 | 弹窗里点允许 拒绝了就去管理器里手动授权 |
| 模块 | 已安装 显示版本号 | 回第 1 步 |
| 模块作者 | `XKspeed` | 换成官方发布的那份 |

三项全绿才给过 这里拦你 比进了主界面点不动要好 

### 第四步：音量键校验

**这一步别跳**  它是整个救砖流程的最后一根绳子 

原理很简单：界面崩了之后 屏幕上什么都点不了 你唯一能输入的就是实体按键 所以应用要确认——音量键按下去 系统真的能读到事件 

校验过程：

1. 屏幕提示「请按一次【音量 +】」 **10 秒内**按一下音量加 
2. 显示「音量 + 校验成功」 接着提示按【音量 −】 
3. 两颗都读到 提示「校验通过 已写入模块配置」 

它会做三件事：

- 按内核能力位（`KEY_VOLUMEUP` / `KEY_VOLUMEDOWN`）找到候选输入设备 不靠设备名猜 
- 让你真按一次 读到事件才算数 
- 记下当前系统版本 **系统升级后版本对不上 旧结果自动作废** 下次打开重新校验 

校验失败分三种 处理方式不同：

| 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| 没读到音量 + | 10 秒内没收到事件 | 点重试 按住键 1 秒再松 |
| 未识别到音量 + 设备 | 内核没声明这颗键 | 检查按键是否坏了 实在不行只能跳过 |
| 按键能读到 但写入配置失败 | 读到了 写不进模块配置 | 去「设置 → 音量键校验」重新来一次 |

跳过校验也能进主界面 但设置里会一直显示「未校验 · 救砖时音量键可能没反应」 看到这行 就别拿它去换重要界面 

> **设置里还能重新校验**  「设置 → 音量键校验」 随时可以重来 系统升级后如果发现状态变回「未校验」 就是这个原因 

### 第五步：完成

点「开始使用」进主界面 以后想重看这套引导 去「设置 → 调试 → 重新查看引导」 不用清数据 

## 3 · 先把运行模式打开 {#step3}

**这是最容易漏的一步 也是新手最常问「点了开始怎么没反应」的原因** 

模块默认是「完全禁用」——装好但什么都不做 这是故意的：默认静默 避免有人装完不知道的情况下被改了什么 

去「设置」 第一项就是**运行模式** 三档：

| 档位 | 行为 | 什么时候用 |
| --- | --- | --- |
| 完全禁用 | 不记日志 不启动守护 | 默认值 平时不用时 |
| 仅日志 | 只抓崩溃日志 不救砖 | 只想看看崩不崩 |
| **日志 + 救砖** | 抓日志 + 音量键救砖 |** 换界面时必须选这个** |

选「日志 + 救砖」 选完系统会把 AMS 的崩溃次数上限从 12 抬到 30 这样 SystemUI 崩几次之后不会立刻被系统收走 你才有时间按音量键 

选完回界面页 状态区不再显示「日志已禁用」就对了 

## 4 · 备好救砖包 {#step4}

进「界面」页 第一行是**救砖界面** 

这里选的 就是 1.3 塞进压缩包的那一份 已经存好了的话 直接选同一个文件即可 

点它 → 会拉起 **MT 管理器**（正版优先 没有就用共存版）→ 选一份 APK 

### 选什么

必须是一份**能正常开机**的 SystemUI 如果 1.3 已经复制过了 你手上那份就是 还没准备的话 两个来源：

1. 从当前系统里提取：`/system_ext/priv-app/MiuiSystemUI/MiuiSystemUI.apk` 用 MT 管理器复制出来 
2. 从和你机型 系统版本完全一致的官方固件包里提取 

**正在用的这一份 就是最稳的救砖包**  别用「我记得某个版本能用」的包——版本不对可能开不了机 

### 会被拦住的情况

| 提示 | 原因 |
| --- | --- |
| 包名是 `xxx` 不是系统界面 | 选错文件了 必须是 `com.android.systemui` |
| 这个文件不是有效的 apk | 文件损坏 或者根本不是安装包 |
| 未找到 MT 管理器 | 去装一个 |
| 这个管理器没给出真实路径 | 用 MT 的 root 模式再选一次 |

选救砖包时会弹一个红色警告 确认就行 这一步的校验比待测严格得多——救砖包选错 等于没救 

### 第二行：待测界面

同样点进去选 要求一样：**包名必须是 `com.android.systemui`** 

这里很多人会拿一个普通 App 来选 然后看到「包名是 com.xxx 不是系统界面」 不是 bug 界面页只处理系统界面本体 测普通应用去主页 

选完两份 界面上会显示文件名和大小 

## 5 · 换入待测界面 {#step5}

点**开始测试** 

底部弹出确认框 标题是「开始测试」 副标题写着「确认后立即替换界面 随后监听崩溃与音量键」 

点「继续」 **没有等待时间 确认即刻替换** 

接下来发生的事：

1. 待测包被复制到模块目录 
2. 脚本覆盖挂载点上的那一份 
3. 等 SystemUI 重启（PID 变化） 
4. 重启成功后开始抓崩溃日志 进入守护 

### 怎么判断成功

| 现象 | 说明 |
| --- | --- |
| 状态变成「守护中 · PID xxxxx」 | 成功 脚本在跑 |
| 屏幕黑一下 / 状态栏闪一下 | 正常 SystemUI 正在重启 |
| 状态区出现「已救砖 0 次」 | 正常 计数从 0 开始 |
| 提示「等待替换界面超时」 | 30 秒内没等到重启 见下 |

### 超时了怎么办

提示原文：`等待替换界面超时（30秒），未检测到 SystemUI 重启` 

意思是包换进去了 但界面没重启 可能：

- 待测包和原来那份**大小完全一样** 覆盖后系统没察觉（脚本对同大小的情况用了 `dd` 原地覆盖 多数能触发 少数机型不行） 
- SystemUI 卡住了 没有自己重启 

处理：手动重启一次手机 看界面是否变成待测的样子 如果重启后直接黑屏 按第 7 节的流程救 

### 停止测试

状态区的「停止」 停掉会结束守护进程和日志抓取 **但不会把界面换回去**——界面还是待测的那份 只是没人盯着了 

停之前先想清楚：还要不要留一条后路 

### 想换回原样

三种方式 按顺手程度排：

1. **按音量加**：守护会把救砖包换回去 最快 几秒 
2. **停掉测试 把救砖包再当待测选一次**：等于主动替换回原版 
3. **卸载模块 + 重启**：最彻底 模块目录里的东西都不再挂载 

前两种要求守护还在跑 第三种随时可用 

## 6 · 守护中会发生什么 {#daemon}

守护跑起来之后 正常用手机就行 它在做三件事：

### 6.1 音量 + ：立刻换回

按一下**音量加** 脚本立刻把救砖包换回去 重启 SystemUI 几秒后界面恢复成原来的样子 

### 6.2 音量 − ：取消这次救砖

误触了 或者想再看看 按音量减可以取消 要在救砖真正执行前按 

### 6.3 自动救砖

开了「增强救砖」之后 累计崩溃次数到达阈值（默认 3 次）也会自动换回 

判定不只看次数 还会看：

- 崩溃日志短时间内疯长（连续两轮 每轮涨超过 2MB 说明在刷屏） 
- 堆栈行占到 80% 以上（典型的 StackOverflow 死循环） 
- `WATCHDOG KILLING` `ANR in com.android.systemui` `Process com.android.systemui has died` 这类明确信号 

任何一路命中都会触发换回 不用等你按音量键 

### 6.4 状态卡上的字段

| 字段 | 含义 |
| --- | --- |
| 守护中 / 未在运行 | 脚本进程是否还活着 |
| `PID xxxxx` | SystemUI 当前进程号 |
| 已救砖 N 次 | 累计成功救砖次数 写在模块配置里 重启不清零 |
| 系统救援已屏蔽 | AMS 崩溃上限被抬高到 999999 |
| 模块 v1.5.5 | 模块版本 和更新提示有关 |

### 6.5 一个必须知道的事实

**守护只在本次开机 本次测试期间有效** 

它不是开机自启的常驻服务 模块开机时只抓 60 秒崩溃日志 不跑救砖守护 守护是你点「开始测试」那一刻由应用拉起来的 手机一重启就没了 

所以：

- 换完界面觉得没问题了 可以不重启 继续用 
- **一旦重启 坏界面就成了「没有守护的坏界面」** 音量键也救不了 
- 重启前先确认界面能正常用 

## 7 · 真崩了怎么救 {#rescue}

按严重程度分四种情况 

### 情况一：界面还在 但卡 / 花屏 / 一直弹错

按**音量加** 等 5～10 秒 SystemUI 会重启 界面恢复 

### 情况二：黑屏 但能感觉到手机还活着（有振动 有声音 能截屏）

盲按**音量加** 不用看屏幕 按一下就行 然后等 10 秒 

如果没反应 再按一次——第一次可能刚好在脚本启动的间隙 

### 情况三：重启之后起不来

这是最麻烦的 因为守护已经没了 

**进 Recovery 删模块目录**：

1. 长按电源键强制关机 
2. 按住电源 + 音量加进 Recovery（TWRP / OrangeFox 都行） 
3. 文件管理器进 `/data/adb/modules/` 
4. 把 `systemui_mount` 整个文件夹删掉 或者在里面建一个空文件叫 `disable` 
5. 重启 

模块一停 挂载就没了 系统会用回自己原来的 SystemUI 界面正常 

### 情况四：开机循环 / 卡在 logo

同上 进 Recovery 删模块目录 

如果 Recovery 也进不去：

- 尝试安全模式（开机时按住音量减 不同机型方式不同） 
- 通过 adb（如果开了 USB 调试）：`adb shell su -c "rm -rf /data/adb/modules/systemui_mount"` 
- 都不行只能刷回官方固件 **这就是为什么换之前一定要有能开机的救砖包 以及别在只有一台手机的时候折腾** 

### 救不回来的原因

救砖包本身也是坏的——换回去还是黑屏 这种情况没有软件办法 只能刷机 所以第 4 节反复强调：救砖包必须是**确认能开机**的那一份 

## 8 · 主页：测任意 APK {#test}

主页是另一套流程 和模块守护完全无关 脚本 进程 日志都在应用私有目录 卸载应用就清干净 

### 8.1 它到底测什么

流程是：**装待测 APK → 立刻开始抓崩溃日志 → 抓满设定时长 → 给结论** 

它不启动应用 也不模拟操作 装完之后**你自己去打开 去用** 它只负责在旁边记录有没有崩 

### 8.2 最常见的用法：测 SystemUI 插件

`miui.systemui.plugin` 这类插件 崩了会让状态栏错乱 但不会像换 SystemUI 那样直接黑屏 

- 待测 APK：新版插件
- 救砖 APK：当前在用的旧版插件
- 目标包名：`com.android.systemui`（插件崩在宿主进程里）
- 自动替换：打开

崩了就把旧版装回去 然后重启 SystemUI 界面恢复 

### 8.3 测普通应用

- 待测 APK：新版本
- 救砖 APK：旧版本（可选）
- 目标包名：**填那个应用的包名** 不是 `com.android.systemui`

目标包名是判定依据：日志里出现 `Process: 这个包名` 才算它崩了 填错等于白抓 

> 注意：这是**覆盖安装**（`pm install -r`） 会替换掉手机上已装的同包名应用 签名不一致会直接安装失败 那就先用 MT 管理器把旧版卸载干净再试 

不知道怎么查包名：MT 管理器打开 APK 看 `AndroidManifest.xml` 或者应用详情页最下面 

### 8.4 步骤

1. 点「待测apk」选文件（同样走 MT）
2. 点「救砖apk」选旧版本（想自动替换就必须选）
3. 点「配置」改目标包名 抓取时长 日志大小判定
4. 打开「自动替换」（可选）
5. 点「开始测试」→ 底部确认 → 继续

确认后立刻开始安装 装完马上开抓 中间没有等待 

### 8.5 三个配置项

点「配置」进去能改三项：

- **目标包名**：默认 `com.android.systemui` 用来判定哪个包崩了 
- **抓取时长**：默认 30 秒 从装完开始算 下一轮生效 测普通应用建议 60～120 秒 够你打开用一会儿 
- **日志大小判定**：默认 5 KB crash 日志超过这个体积也算崩 兜住拿不到包名的机型 设 0 关闭 

### 8.6 结果怎么读

跑完会在状态区给一句结论：

| 结论 | 意思 |
| --- | --- |
| 未检测到崩溃 | 这段时间内没崩 不代表以后不崩 |
| 检测到崩溃 未执行救砖 | 崩了 但没开自动替换 |
| 已自动救砖 | 崩了 旧版本已装回 SystemUI 已重启 |
| 救砖失败 | 装回失败 看日志 |
| 日志目录不可写 | 设置里的日志目录没权限 换一个 |

### 8.7 自动替换的两个限制

- **每轮最多救一次**  救完继续抓日志 但不会再救第二次 
- **距上次救砖 300 秒内不再救**  防止连环装包把手机拖死 

### 8.8 两个包不能选的情况

| 提示 | 原因 |
| --- | --- |
| 待测apk不能和救砖apk是同一个文件 | 崩了装回同一份 等于没救 |
| 这个包不能装（提示去界面专区） | 待测是 `com.android.systemui` 用界面页 |
| 救砖apk不能是系统界面 | 救砖包也不能是 SystemUI 本体 |

## 9 · 设置逐项说明 {#settings}

### 运行

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 运行模式 | 完全禁用 / 仅日志 / 日志 + 救砖 | 换界面选第三档 |
| 日志目录 | 崩溃日志存哪 默认 `/data/media/0/log区` | 别选 `Android/data` 下面 容易写不进 |
| 缓存大小 | 进缓存管理页 | 见下 |
| 等待超时 | 换完界面等 SystemUI 重启的秒数 10～60 | 默认 30 慢机型调到 45 |

### 自动救砖

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 音量键校验 | 重新校验音量键 | 系统升级后必做 |
| 增强救砖 | 崩溃到阈值自动换回 | 换重要界面前打开 |
| 崩溃阈值 | 累计几条 fatal 自动救 1～10 | 默认 3 替换本身可能崩一次 别设 1 |
| 屏蔽系统救援 | 把 AMS 崩溃上限拉到 999999 | 开增强救砖时强制开启 不可关 |

> **为什么开了增强救砖就必须屏蔽系统救援：** 不屏蔽的话 SystemUI 崩到系统的上限（默认 12）就被系统收走了 脚本还没来得及执行 自动救砖等于没有 

### 调试

| 项 | 说明 |
| --- | --- |
| 应用日志等级 | 关闭 / 仅错误 / 警告 / 常规 / 详细 / 全部 排查「设置了没生效」看这里 |
| 应用日志内容 | 看应用自己的运行记录 |
| 模块调试日志 | 打开后脚本每一步写进 `config/debug.log` 很啰嗦 只在排查时开 |
| 调试日志预览 | 直接看脚本输出 不用去翻文件 |
| 调试选项 | 高级开关 看不懂别动 |

### 缓存

界面页选的 APK 会复制一份到应用私有目录 因为模块脚本需要一个稳定的副本——你随时可能把下载目录里的原文件删了 

缓存页可以看到每个文件占多少 勾选删除 删了不影响当前正在跑的测试 但下次换界面要重新选包 

上限五档 无限制 / 100 MB / 200 MB / 500 MB / 1 GB 超过自动清最旧的 拖滑条或者直接点下面那排档位都能改 

### 关于

- 应用版本 模块版本
- 模块有新版本时会显示「可更新」 点进来看更新日志 可以只下载 zip 不自动安装
- 检查更新会同时查应用和模块
- 自动检查更新：启动时看一眼 默认开

## 10 · 日志与求助 {#log}

出问题别只发一句「用不了」 日志能省掉十轮来回 

三种日志 用途不同：

| 日志 | 位置 | 看什么 |
| --- | --- | --- |
| 运行日志 | 设置里的日志目录 文件名是时间 | 崩溃现场 `FATAL EXCEPTION` `Process: xxx` |
| 调试日志 | 模块 `config/debug.log` | 脚本每一步 替换成没成功 PID 变没变 |
| 应用日志 | 设置 → 应用日志内容 | 应用侧的动作 比如「写配置失败」 |

求助时给这几样：

1. 机型 + 系统版本（例：Xiaomi 15 HyperOS 3.0.2 Android 16）
2. 模块版本 + 应用版本
3. 你做了什么（选了什么包 点了什么）
4. 看到了什么（截图或原文提示）
5. 对应的日志文件

## 11 · 常见问题 {#faq}

**Q：点了开始测试 显示已启动 但状态还是「未在运行」**  
运行模式没开 去设置选「日志 + 救砖」 见第 3 节 

**Q：选了 APK 提示「包名是 xxx 不是系统界面」**  
界面页只收 `com.android.systemui` 测普通应用去主页 

**Q：提示「未找到 MT 管理器」**  
选文件走的是 MT 不经过系统选择器 装一个 正版共存版都行 

**Q：换完界面黑屏了 按音量加没反应**  
先确认守护还在（状态是「守护中」） 如果手机重启过 守护已经没了 走第 7 节情况三 

**Q：换完一直停在「等待替换界面」**  
等 30 秒会超时 手动重启一次看效果 重启后黑屏就走 Recovery 删模块 

**Q：KernelSU 下模块装了 界面完全没变化**  
两种可能：没装元模块 或者 zip 里没放 `MiuiSystemUI.apk` 见 1.2 和 1.3 

**Q：重启后界面变回原样了**  
说明模块没生效 或者被删了 回模块列表看状态 描述里写「待重启」就再重启一次 

**Q：音量键校验一直失败**  
先确认键本身没坏（在别的界面按音量能看到音量条） 有些机型音量键走的是 `qpnp_pon` 读事件需要 root 权限 确认应用已授权 

**Q：增强救砖打开后「屏蔽系统救援」变灰了**  
正常 两个绑死 开了增强就必须屏蔽 否则轮不到脚本执行 

**Q：救砖次数一直涨**  
说明待测界面在反复崩 别继续用了 换一份稳定的包 

**Q：能不能不 Root**  
不能 挂载和重启 SystemUI 都需要 root 

**Q：能不能换其他系统（AOSP / 三星 / 一加）**  
脚本针对 `MiuiSystemUI` 的路径和包名写的 别的系统不保证能用 

**Q：模块和应用版本必须一致吗**  
不必 但建议一起更新 应用会读模块配置 字段对不上会显示不全 

**Q：卸载模块会怎样**  
挂载消失 系统回到自带界面 已经换进去的文件还在模块目录里 重新装模块会读回来 

**Q：更新应用会丢配置吗**  
不会 配置在模块目录里 不在应用数据里 但卸载模块会丢 

## 12 · 最后 {#end}

这套东西的价值不在于「能换界面」 而在于**换坏了能回来** 

所以每次折腾之前 花两分钟确认三件事：

1. 救砖包是能开机的那一份 
2. 音量键校验过了 
3. 运行模式是「日志 + 救砖」 

三条都在 你就有退路 少一条 就是在赌
