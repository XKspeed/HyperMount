使用教程

第一次用建议从头看一遍，尤其是第 3 步——那一步决定你出事之后能不能回来。

开干之前

项目要求
系统Android 15（API 35）及以上，HyperOS / MIUI 类系统
权限已 Root：Magisk / APatch / KernelSU 任一
模块与本应用配套的 systemui_mount 模块，作者需为 XKspeed
应用arm64 安装包，可直接覆盖升级
这不是免 Root 工具。它做的事情是替换 SystemUI 并重启它，没有 Root 一步都走不了。

1 · 装模块

  1. 下载配套模块的 zip，在 Root 管理器里「从本地安装」，刷入后重启手机。
  2. 重启后确认模块处于启用状态。应用首次启动会做环境检查，读不到模块或作者不是 XKspeed 会直接拦住——这说明装的不是配套模块，脚本调不起来。

模块负责挂载、备份与恢复 SystemUI，应用只是它的控制面板。两者版本不必严格一致，但建议一起更新。

2 · 装应用

安装后首次打开会走一遍引导，四屏：

  1. 欢迎：确认这是干什么用的。
  2. 须知：替换系统界面有风险，先备好救砖界面。
  3. 环境检查：Root 是否可用、模块是否装好、作者是否正确。
  4. 音量键校验：这一步别跳过，见下。

为什么一定要校验音量键

「音量 + 救砖」是界面已经点不动时唯一的输入方式。但内核声明了有音量键，不代表真能按出事件——按键可能被映射到别处、设备号也可能在系统升级后变化。所以应用会：

  • 按能力位（KEY_VOLUMEUP / KEY_VOLUMEDOWN）找到候选输入设备；
  • 让它真的按一次，确认能读到事件，才把设备号写进模块配置；
  • 记下这次校验时的系统版本。系统升级后版本对不上，旧的校验结果自动作废，下次启动重新拉起校验面板。
校验结果写在模块配置的 saved_assess 里，设置页只显示「已识别 / 未识别」。显示「已识别」= 脚本真的拿到过按键事件，不是猜的。

3 · 备救砖界面

进「界面」页，第一行是救砖界面。点它，选一份确认可用的 SystemUI APK。

  • 来源可以是当前系统里提取的 MiuiSystemUI.apk，也可以是之前备份好的文件；
  • 选择器直接拉起 MT 管理器（正版优先，否则共存版），不经过系统文件选择器；
  • 落地后先读安装包清单校验包名，不是 com.android.systemui 的一律拒收——防止误选成普通应用，装回去等于没救；
  • 下载器留下的 apk.1 后缀会自动还原成 .apk。

第二行是待测界面，选你要实测的那一版。这里不校验包名，但要保证它确实是一份可用的 SystemUI。

4 · 换入待测界面

两份都选好后，点开始。守护进程接管，把待测界面换进去并重启 SystemUI。

接下来正常用手机就行。守护会盯着崩溃日志，满足任一条件就自动换回救砖界面：

条件说明
崩溃次数到阈值累计 fatal 条数达到设定值，默认较保守，增强救砖模式可调
判定为卡死日志疯长 / 堆栈刷屏，单次就可能几万行，不靠次数也能触发
音量 + 按下手动立刻换回，不用等阈值

三个开关之间的关系

设置行为
运行模式完全禁用 / 仅日志 / 日志 + 救砖。带日志才出现「日志目录」和「等待超时」
增强救砖崩溃达到阈值自动替换。开启后强制屏蔽系统救援且不可关闭
屏蔽系统救援拉高 AMS 崩溃次数上限，避免系统抢在自动救砖前杀掉 SystemUI
崩溃上限「日志 + 救砖」模式下自动设为 30；增强救砖下可自己调
为什么开着增强救砖就必须屏蔽系统救援：不屏蔽的话系统会先崩到自己的上限把 SystemUI 收走，自动救砖根本没有机会执行。

真崩了怎么办

如果界面黑屏、卡死，但系统还活着：

  1. 先按音量 +。守护在跑的话直接换回，几秒后 SystemUI 重启。
  2. 按音量 −可以取消本次救砖，误触时用。
  3. 都不行，进 Recovery 或安全模式，用模块自带的恢复能力换回备份。

救完一次之后，界面上会累计「已救砖 N 次」，这个数字在状态卡里能看到。

主页的独立测试

「主页」是另一套流程，不依赖模块守护，用于测别的 apk 会不会崩：

  • 自己往 /data/local/tmp 丢一份脚本跑，跑完即删；
  • 流程是：后台安装待测 apk → 等「等待时长」→ 抓 crash 日志；
  • 开启「自动替换」后，日志超过阈值就把救砖 apk 装回去并重启 SystemUI；
  • 不校验包名，测的可以不是 SystemUI，只拦「待测 apk 和救砖 apk 是同一个文件」。
主页的待测 apk 拒绝 com.android.systemui：那是「界面」页干的活，在主页装成系统界面本体容易直接黑砖。

日志与排查

设置页「调试」里有两套日志，用途不同：

日志用途
应用日志应用自身的运行记录，带等级：关闭 / 仅错误 / 警告 / 常规 / 详细 / 全部。排查「设置了没生效」看这里
调试日志脚本每一步动作，落在模块 config/debug.log
运行日志抓取到的 SystemUI crash 输出，落在「日志目录」

日志目录可以直接改：点一下弹系统文件夹选择器，选完立即写入并回读确认，写不进去会直接提示。改目录只影响下一次抓取。

崩溃堆栈单独存一份，清空日志不会把它删掉，出问题先看它。
