# HyperMount

一个 **SystemUI 界面替换与自动救砖** 的控制端 App 小米 HyperOS 风格界面

围绕「**备好救砖界面 → 换入待测界面 → 崩了自动换回 → 继续正常使用**」这条主链路设计：放胆把会崩的界面换进去试 出事自动换回可用的那一版 不再怕 SystemUI 黑屏卡死

## ✨ 功能

### 救援流程
- **救砖界面**：选一个确认可用的 SystemUI 留作后路 出事时换回它
- **待测界面**：选要实测的那一版界面 换进去观察
  - 点选文件直接拉起 MT 管理器（正版优先 没装再走共存版）
  - 两个版本都没装时会提示找不到 MT 管理器 不会退回别的选择器
  - 下载器留下的 `apk.1` 后缀会自动还原成 `apk`
  - 复制完成先校验包名 不是 `com.android.systemui` 的一律拒收
- **开始 / 停止**：一键接管 随时可以喊停

### 自动恢复
- **崩溃阈值**：累计多少条崩溃日志后自动换回救砖界面（可调）
- **卡死检测**：日志疯长、堆栈溢出同样算卡死 不必等崩溃次数攒够
  - 这类崩溃单次就能刷出几万行 但频率极低 靠次数永远等不到 只能靠它兜住
- **等待超时**：换完界面后等 SystemUI 重启的秒数（可调）
- **音量键救砖**：音量 + / 音量 - 直接换回 界面已经点不动时也能救
- **屏蔽系统救援**：把系统的崩溃次数限制拉高 避免系统抢在前面杀掉 SystemUI
  - 开启**增强救砖**时强制打开 且不可关闭 否则系统先崩到上限 自动救砖根本没机会执行
  - 日志 + 救砖模式（不开增强）下崩溃上限设为 **30** 比系统默认的 12 宽 音量键才来得及按

### 音量键
- 自动认出设备的音量键 并逐个实测是不是真能按出事件（声明了 ≠ 真能按）
- 测一次就记下来 之后直接用 不用每次重测

### 主页（独立测试）
- 不依赖模块守护 自己跑一套测试流程 测别的 App 崩不崩也能用
- 流程：装待测 apk → 等设定的时间 → 只抓崩溃日志 → 崩了自动把救砖 apk 装回去
- **不校验包名** 测的可以不是 SystemUI 只拦「待测 apk 和救砖 apk 是同一个文件」
- **自动替换**：关掉也能正常测试 只是少了崩溃后换回救砖 apk 这一步
- 主页和「界面」页各存各的 apk 互不影响
- **配置项**：点开是底部弹窗 目标包名 等待时长（0 到 20 秒） 抓取时长（5 到 60 秒）
- 运行日志实时回显在状态卡里 救砖次数也在这里数
- 日志落在设置页「日志目录」指定的位置（设置页运行模式带日志时才出现 点卡片直接改路径）
- 目标包名与待测 / 救砖 apk 的包名无关 测插件时崩溃记在宿主名下 所以可以随便填
- 所有滑动条都支持点标题区域直接敲数值
- **崩溃日志**：独立的崩溃记录页
- **调试日志**：可开关 记下每一步动作

### 检查更新
- 启动时后台查一次 有新版就在主页版本号右侧亮出更新胶囊 点一下直达下载
- 设置页「关于」里的「检查更新」可手动复查 期间整行变灰不会重复点
- 同一张卡里的「自动检查更新」开关可以关掉启动时那次检查
- **更新来源**可选正式版或内测版 想尝鲜切到内测版 不需要了切回正式版即可
- 查到的结果会记住 断网或者重启 App 都不会把更新提示弄丢

### 界面
- Miuix 风格 支持深色模式 顶栏是可收缩的大标题
- **底栏三页**：界面 / 主页 / 设置 只能通过底栏切换 左右滑动不再翻页 避免误触
- **主题**：一张卡里放主题模式（跟随系统 / 浅色 / 深色）· 莫奈取色 · 种子色（含调色风格与色彩规范）
- **模糊强度**：玻璃控件的模糊程度可调 拖动即时生效
- **预测性返回手势**：根据手势预览上一级 关闭后拖动时页面不动 松手才返回 圆角按系统圆角裁切
- **底栏折射**：关闭后退化为磨砂胶囊 不做折射

### 关于
- 入口在设置页最下面 点进去是二级页
- 应用版本 模块版本 最低系统
- **第三方许可证**：开源库清单与许可证 独立二级页
